# ADR-0002: 웹 앱 분리와 공통 UI 기반

- 상태: 채택
- 날짜: 2026-11-08
- 구현·검증: 관리자 공통 기반 구현과 로컬 검증 완료. 원격 CI·실제 배포·고객 및 CS 앱은 별도 검증 대상.

## 배경

Etude는 계속 개발해 공개할 수 있는 서비스를 목표로 한다. 관리자 화면을 시작으로 고객 쇼핑몰과 CS 화면이 필요할 수 있어 앱별 독립성과 공통 UI의 재사용 경계가 필요하다. 현재는 BE 연동보다 공통 UI와 보안 기준을 먼저 마련한다.

초기 Mantine 기반 화면을 검토한 뒤, 저장소 주인은 최근 제품 UI의 디자인과 한글 표시 품질을 기준으로 shadcn/ui 전환을 승인했다. 이 ADR은 아직 main에 반영되지 않은 공통 기반 작업의 최종 선택을 기록한다.

## 결정

1. npm workspaces로 `apps/admin`, `packages/ui`, `packages/config`를 분리한다. 고객·CS 앱은 필요할 때 별도로 추가한다.
2. 관리자 앱은 React + TypeScript + Vite + React Router로 구성하고 정적 배포가 가능하도록 한다. 고객 앱의 프레임워크는 이 결정으로 고정하지 않는다.
3. UI는 공식 shadcn CLI의 `base-nova` 스타일과 Base UI 컴포넌트를 가져와 사용한다. Tailwind CSS로 공통 토큰을 관리하고 Lucide 아이콘과 자체 호스팅 Pretendard Variable을 사용한다.
4. 공통 패키지는 앱·라우터·업무 규칙에 의존하지 않는다. 관리자 메뉴와 레이아웃은 관리자 앱이 관리한다.
5. 외부 스크립트·폰트 CDN 없이 UI를 제공하고, CSP와 보안 헤더를 배포용 빌드에서 검증한다. 실제 인증·API 연결은 별도 설계한다.

## 대안과 선택 이유

| 대안 | 장점 | 판단 |
| --- | --- | --- |
| Mantine | 설치형 라이브러리, 풍부한 컴포넌트와 테마 기능 | 유효한 대안이지만 실제 화면 검토 후 주인의 디자인 선호에 따라 전환했다. 기능이나 보안이 부족해서 배제한 선택은 아니다. |
| MUI | 다양한 업무 UI와 완성형 무료 템플릿 | 설치형 라이브러리의 관리 편의는 있으나 현재 승인된 디자인 방향은 shadcn/ui다. X 고급 기능의 라이선스는 별도로 확인해야 한다. |
| Ant Design | 표·폼 중심 관리 화면에 적합 | 현재는 업무 기능보다 여러 앱의 공통 기반과 승인된 시각적 방향을 우선한다. |
| Next.js 관리자 | 통합 라우팅, 정적 생성, 서버 기능 | 현재 관리자에 서버 기능 요구가 없다. 고객 앱이나 문서별 사전 렌더링 요구가 생기면 재검토한다. Next.js도 정적 배포를 지원한다. |
| 한 앱에 관리자·고객 화면 배치 | 초기 설정이 적음 | 메뉴·권한·프레임워크·배포가 결합되므로 독립 앱을 선택했다. 앱 분리는 인증·인가를 대신하지 않는다. |

## 트레이드오프

- shadcn/ui는 소스를 가져오는 방식이다. 컴포넌트 업데이트와 로컬 수정을 프로젝트에서 검토해야 한다. 출처와 수정 범위를 공통 UI README에 기록한다.
- CLI 버전 고정만으로 원격 레지스트리 내용을 고정하지는 못한다. 실제 커밋된 컴포넌트 소스와 잠금 파일을 기준으로 검토한다.
- 정적 배포는 FE 서버 운영 범위를 줄일 뿐 XSS·공급망 취약점·공개 파일 유출을 해결하지 않는다. 스타일 속성은 팝업 위치 계산에 허용하되 인라인 스크립트와 스타일 태그는 제한한다.
- Pretendard는 Unicode 서브셋을 같은 출처로 제공한다. 글꼴 변경·서브셋 로딩과 첫 표시를 실제 배포 환경에서도 확인해야 한다.
- 공통 UI 소스는 소비 앱이 빌드한다. Next.js 추가 시 client 경계·transpile 설정·Tailwind 소스 탐색을 검증한다.
- 실행과 검증 방법, 보안 정책의 구체적인 한계는 [web/README.md](../../web/README.md)를 기준으로 관리한다.

## 검증 결과와 한계

- Windows / Node.js 22.14.0에서 타입·코드·포맷·프로덕션 빌드 검사를 수행했다.
- Chromium 데스크톱·모바일 에뮬레이션에서 경로, 테마, 키보드, 대화상자·알림, 입력·선택·표 검색, 화면 검색, 한글 폰트와 CSP를 검증한다. 최종 실행 결과는 PR에 기록한다.
- 전체 의존성 감사에는 shadcn CLI의 deepmerge 관련 low 항목이 남아 있다. 브라우저 런타임과 개발 도구의 범위를 구분하며 강제 다운그레이드로 숨기지 않는다.
- 실제 배포 헤더·HTTPS, 다른 브라우저, 중첩 대화상자, 인증·API·실제 모니터링, 고객·CS 앱은 현재 검증 범위에 포함하지 않는다.

## 재검토 조건

문서별 사전 렌더링·검색 노출이나 인증 중계 서버가 필요해지거나, 공통 UI가 고객 화면의 요구를 충족하지 못하거나, UI 갱신 비용이 관리하기 어려워지면 새 ADR로 선택을 재검토한다.

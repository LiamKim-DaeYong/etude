
# Etude 문서

Etude는 주문·재고·결제 시스템을 중심으로 높은 동시성과 분산 환경에서 발생하는 설계 문제를 탐구하는 프로젝트다.

기술적 의사결정의 근거와 대안을 기록하고, 구현 및 실험을 통해 검증한 결과를 문서화한다. 설계 목표와 실제 구현·검증 범위는 구분하여 기술한다.

## 용어집

[용어집](glossary.md)은 업무 용어와 이름 규칙의 기준이다. 한글 용어, 코드·API 이름, 정의, 쓰지 않는 말을 모듈별로 정리한다.

## 설계 결정 (ADR)

주요 기술 선택은 ADR(Architecture Decision Record)로 관리한다. 각 문서에는 결정 배경, 검토한 대안, 트레이드오프(Trade-off), 검증 결과와 한계를 기록한다.

| 번호 | 주제 | 결정 | 상태 | 구현·검증 |
| --- | --- | --- | --- | --- |
| ADR-0001 | [엔티티 식별자](decisions/0001-entity-identifiers.md) | UUIDv7 채택 | 채택 | 로컬 검증 완료, 모든 엔티티에 적용(`BaseEntity`) |
| ADR-0002 | [웹 앱 분리와 공통 UI](decisions/0002-web-foundation.md) | 독립 앱과 shadcn/ui 공통 기반 | 채택 | 관리자 기반과 로컬 검사 완료, 원격 결과는 Web CI에서 확인 |
| ADR-0003 | [재고 예약의 동시성 제어](decisions/0003-inventory-concurrency-control.md) | 비관적 락, 락 대기 2초 후 503 | 채택 | 초과 판매 재현·해결 통합 테스트 완료, 방식별 성능은 미측정 |

## 문서 관리 원칙

- **ADR:** `decisions/NNNN-topic.md` 형식으로 관리한다. 결정 배경, 대안, 근거, 검증 결과, 한계 및 재검토 조건을 기록한다.
- **결정 상태:** 제안·채택·대체·폐기로 구분한다. 기존 결정을 변경할 때는 새 ADR을 작성하고 이전 결정과 연결한다.
- **구현·검증 상태:** 의사결정 상태와 별도로 관리한다. 채택한 기술이라도 실제 적용하거나 검증하지 않았다면 이를 명시한다.
- **개념 노트:** `learning/topic.md` 형식으로 관리한다. 개념과 예시를 설명하되 프로젝트의 선택 근거는 ADR을 참조한다.
- **실험 결과:** 측정값에는 환경, 실험 조건 및 결과의 적용 범위를 명시한다.
- **용어:** [용어집](glossary.md)의 용어를 쓴다. 용어를 추가하거나 바꾸는 PR은 같은 PR에서 용어집을 고친다.
- **기술 서술:** 요구사항, 설계 가정, 기술적 결정, 측정 결과와 미검증 영역을 구분한다. 동일한 내용을 여러 문서에 중복 기록하지 않는다.
